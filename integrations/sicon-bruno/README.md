# Sicon ↔ Pulse — Bruno mapping package

Generated by `backend/scripts/gen_bruno_sicon_mapping.py` (re-run any time the
mapping or Sicon collection changes). **No credentials are stored in this package.**

## What's here
- `collection/` — Sicon's official Service WebAPI Bruno collection + a secure
  `environments/Plugin Platform.bru` and a best-effort `Auth/Authenticate.bru`.
- `FIELD_MAPPING.md` — every Sicon request-body field joined to its Pulse field,
  grouped by entity, with direction (→ push / ← pull / ↔ both) and MAPPED/UNMAPPED.
- `mapping.csv` — the same, spreadsheet-friendly for the Sicon team.

## Run it in Bruno (on your machine — the API is on your LAN at localhost:51080)
1. Open Bruno → Open Collection → select this `collection/` folder.
2. Create `collection/.env` from `.env.example` and paste your password:
   `SICON_PASSWORD=«the password»`  (`.env` is git-ignored — never committed).
3. Select the **Plugin Platform** environment (baseUrl `http://localhost:51080`,
   username `Administrator`, companyId `2`).
4. Run **Auth → Authenticate** to populate `BEARER_TOKEN`
   (⚠ confirm the exact auth URL/body against the Sicon.WebApi.Platform collection
   Sicon gave you — the platform auth route is not in the Service zip).
5. Run **Core → Ping** (anonymous) to confirm connectivity, then any Case/Appointment/
   Equipment request. Set collection vars (`caseId`, `caseTypeId`, `priorityId`, …)
   before Put/Post writes so you don't hit live records by accident.

## Security
- Password is referenced as `{{process.env.SICON_PASSWORD}}` from `.env` only.
- `.gitignore` excludes `.env`. `.env.example` ships blank.
