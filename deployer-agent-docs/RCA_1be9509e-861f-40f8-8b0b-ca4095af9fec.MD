### WHY only 19 of 51 are on the live version — ROOT CAUSE
This is a **multi-replica boot race**, proven by the boot logs in §1. At the 13:54:53 rollout, two backend replicas BOTH ran the Year-4 Schedule-B bootstrap concurrently with no distributed lock / idempotency guard. Each created its OWN live price-list version:
- one replica created `SOR-2026-11-25-f0f81b` and stamped 24 rate-card rows to it (and classified 0),
- the other created `SOR-2026-11-25-af73ec` and stamped 19 rows to it (and reclassified 30 / marked 27 historical).

Only `af73ec` won the "live" slot; `f0f81b` was flipped to `superseded`. Result: the 24 rows carrying `f0f81b` now point at a superseded version, the 5 legacy rows + 3 POA rows were never attached to any version, and only the 19 rows carrying `af73ec` equal the live version. The data itself is intact and priced — it is a version-pointer/attachment problem, not missing prices.
