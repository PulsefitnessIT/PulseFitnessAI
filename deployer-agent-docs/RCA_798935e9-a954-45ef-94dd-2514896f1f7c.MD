## Finding (1) — what modservice.pulsefitness.com is bound to
`modservice.pulsefitness.com` is **NOT** a custom domain on this deployment. It does not appear in `list_domains` nor in `check_domain_status` for `fitness-ai-migrate`. Therefore it is bound to a **different / older Emergent deployment slot** (a separate deployment — likely a prior deployment of the same app or another job), which still carries its own stale container image.

Supporting evidence (user-provided curl): modservice serves old bundle `/static/js/main.a3ca8dae.js` (no `is_external_engineer`, etag `7e81320912b7cbbbb83a4041836b4263`), and its backend returns 404 on `/api/mod/site/machine-suppliers` and 404 on the POST-only sicon route — i.e. those routes do not exist in that older image. The current image returns 401 and 405 respectively. Same MongoDB data is visible on both because the old slot points at the same database.

NOTE: My tooling is scoped to THIS deployment only; I cannot enumerate the other deployment to print its exact deployment_id/job_id. What is certain is that it is **not** `1b2301c1-4242-4a5d-90f8-dcbdbf3453ee`.

## Finding (2) — is modservice listed as a custom domain on THIS deployment?
No. Only `pulsefitness.ai` and `www.pulsefitness.ai` are listed.

## Finding (3) — how to point modservice.pulsefitness.com at this deployment
This is a user action (Cloudflare custom hostnames can only be bound to one deployment at a time):
1. **Unlink** `modservice.pulsefitness.com` from the OTHER (older) deployment where it is currently attached — otherwise the Cloudflare custom-hostname binding conflicts and it keeps serving that slot's old image.
2. In **this** deployment (`fitness-ai-migrate`) → **Domains** tab, **Link your Domain** → add `modservice.pulsefitness.com`.
3. Update DNS at the registrar: point `modservice.pulsefitness.com` via **CNAME to the target shown in this deployment's Domains tab** — the Emergent hostname `fitness-ai-migrate.emergent.host` (same target the already-working `pulsefitness.ai` uses). Use the exact record the Domains tab displays.
4. Wait for verification + SSL issuance to go active (as it already is for pulsefitness.ai), then re-curl: modservice should return the current `main.73d3b5dc.js` and the backend should return 401/405 (not 404).
