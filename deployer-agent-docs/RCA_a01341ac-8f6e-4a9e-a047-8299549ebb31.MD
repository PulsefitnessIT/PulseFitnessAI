## Root cause

Two independent problems, both proven by the data:

A) "0 jobs" at /svc/engineer — nothing links the open case to Jimmy:
   - svc_cases a6ed022c.assigned_engineer_id = NULL and territory_id = NULL.
   - user.bfpo_territory_ids = [] and svc_engineers doc has no territory.
   The engineer job list is driven by assigned_engineer_id and/or territory membership; the open BFPO case matches neither, so the list is empty even though the fault is open and "Sent to Supplier" (mod_booking.status=sent).

B) Lands on Operations /dashboard instead of the engineer app:
   - user.account_type = mod_site, is_mod_user=true, is_mod_bfpo=true, organization_id=bfpo-mod-org.
   - role=engineer / bfpo_role=engineer, but the engineer-identity flags the portal router expects are ABSENT: no is_engineer, no service_org_id, no has_staff_portal, no module_access.
   The frontend routes this account shape to the Operations portal (setup wizard) rather than the engineer app, because the engineer-app entitlement fields are not set on the user doc.

## Supporting data inconsistencies (not necessarily the trigger, flagged for E1)
1. organization_id "bfpo-mod-org" has NO organizations document (count 0), yet user, svc_engineer and svc_case all reference it. The service supplier (suppliers 19323066) instead sits under the SITE org (mod-site-royal-gibraltar-reg-davils-tower-camp). So engineer/case org (bfpo-mod-org) and supplier org (site) differ — any join that goes engineer→supplier→case via a single org id will not line up.
