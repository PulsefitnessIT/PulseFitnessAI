## Root cause
William's empty job list is **not** an identity mismatch and **not** a status/casing issue. The engineer endpoint reads `svc_cases` filtered on `assigned_engineer_id`, but **no allocation has been persisted there (all `assigned_engineer_id` are empty) and no PPM record exists in any PPM/scheduling collection.** Whatever the Service Desk PPM calendar appeared to save did not land in the data this endpoint (or any PPM collection) reads.

Two possibilities remain, and they require code/environment confirmation I cannot make from data alone:
1. **Code (most likely):** `POST /api/svc/ppm/schedule` is not persisting the allocation to `svc_cases.assigned_engineer_id` that `GET /api/svc/engineer/jobs` reads — it may write to a different collection/field, or the write silently no-ops/fails. The complete absence of ANY populated `assigned_engineer_id` and ANY PPM-collection row across the whole DB is the strongest signal of a write-path gap, not a read/filter bug.
2. **Environment/User:** the allocation the reporter saw was made in a different environment than this active prod DB (`rbac-modules-test_database`), or was not actually saved.
